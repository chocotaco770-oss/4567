Major Modules

  • Patient registration & management (CRUD + search)
  • Doctor management · specialization · fee · availability
  • Appointments — booking, update, cancel; double-booking prevention
  • Prescriptions · Medical records (chronological history)
  • Billing (auto-calculated) · Payments (interface-driven)
  • Room allocation · Ambulance booking · Reports · Backup/Restore
  • Role-based login: Admin / Doctor / Patient dashboards

Layered Architecture

FXML + CSS Views — 16 screens
↓
Controller Input, alerts, navigation — no SQL, no business rules
↓
Service Business rules, validation, transactions, custom exceptions
↓
Repository JDBC + PreparedStatement, result mapping (11 DAOs)
↓
Database SQLite · data/hospital.db · foreign keys · backup/restore

OOP Concepts

  • Inheritance — Person → Patient, Doctor, Admin
  • Abstraction — abstract Person with abstract displayInformation()
  • Polymorphism — method overriding + PaymentService / ReportGenerator interfaces
  • Encapsulation — private fields, getters/setters, guarded state changes
  • Association — Patient ↔ Appointment ↔ Doctor
  • Aggregation — Hospital holds Patients/Doctors/Rooms/Ambulances
  • Composition — MedicalRecord owns Prescription (cascade delete)
  • Overloading — searchPatient(name) / searchPatient(name, phone)
  • Exceptions — 10 custom exceptions → user-friendly alerts
